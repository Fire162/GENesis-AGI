- **An update killed partway through moving the checkout is no longer recovered over as if nothing had happened.** On the `live` integration branch the rebuild now records how far its checkout move got in the update's own `update_state.json` row (the `live_move` field; the separate `~/.genesis/live_move.json` file is retired and removed), and every reader that judges an interrupted update (bootstrap's crash recovery, `update.sh`, `deploy_code_only.sh`, the dashboard) now sees it. A checkout left half-written, on `live` or on `main` (including by a `live` rollback stopped after the rebuilt code was adopted), gets a new verdict that lists the affected paths and says how to put them back and what to do next, which the dashboard's update card now shows; an unrelated edit elsewhere in the checkout is no longer mistaken for one. `update.sh --post-merge` now refuses such a checkout (exit 5) instead of installing over it, and also refuses when the state check could not run. Bootstrap's crash recovery also treats a still-held `update.lock` as an update that is still running, and proceeds at the rollback tag only when the shared check clears the state. A `live` rollback whose rebuild began moving but wrote nothing now restarts the old code instead of leaving the services down.
